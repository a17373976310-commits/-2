# 高级提示工程规范 (Advanced Prompting)

## 1. 核心设计原则
1. **指令清晰化**：使用明确的动作动词（如 `Extract`, `Evaluate`, `Plan`）。
2. **正面指令优先**：尽可能描述“应该做什么”，避免单一的否定限制。
3. **结构化分隔**：使用 `#`, `##` 或 XML 标签（如 `<context>`, `<rules>`）区分指令和数据。

## 2. 核心技术路径

### 🧩 样本引导 (Few-Shot)
- 当任务涉及特定格式或复杂风格时，提供 3-5 个示例。
- 确保示例覆盖正例和边界情况。

### 🧠 推理增强 (CoT/ToT)
- **思维链 (CoT)**：在复杂逻辑前加入 `"让我们逐步思考 (Let's think step by step)"`。
- **思维树 (ToT)**：对于决策类任务，指示模型 `"探索 3 种可能的路径并评估其优劣"`。
- **反思 (Step-Back)**：指示模型 `"在回答具体问题前，先抽象出其涉及的核心原理"`。

### 🛠️ 行动与交互 (ReAct)
- 设计 `"思考 (Thought) -> 行动 (Action) -> 观察 (Observation)"` 的循环。
- 提供清晰的工具描述，引导模型输出标准 JSON。

## 3. 结构化输出规范
- **强制 JSON**：要求模型以特定 JSON Schema 响应，以确保系统兼容性。
- **校验先行**：在处理输出前，使用 Pydantic 或类似逻辑进行 Schema 校验。

## 4. 元优化流程 (Meta-Prompting)
1. **初始提示词**：尝试完成基础任务。
2. **AI 评审**：将提示词发给模型，要求其分析：“这段提示词可能在哪些场景下产生歧义？”
3. **针对性修正**：根据反馈添加提示词分隔符或具体的约束条件。

## 5. 特定任务模板

### 复杂逻辑提取
```markdown
# 任务：从非结构化文本中提取[实体]
# 限制：必须输出 JSON
# 思考过程：请先分析文本中的实体关系，然后按格式输出。
```

### 提示词优化 (Meta-Prompt)
```markdown
你是一名资深提示词工程师。请分析以下 Prompt 并提出 3 点改进建议，重点在于提高输出的稳定性。
[原始 Prompt]
```
