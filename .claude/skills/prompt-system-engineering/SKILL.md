# 系统级提示词工程框架

## 核心理念
提示词工程 = 自然语言编程
- 不是"聊天"，是在写**结构化代码**
- 目的：让概率性模型输出**确定性**结果
- 方法论：收敛概率空间，堵死错误路径

---

## Prompt 架构模板（四层结构）

```
# ROLE (类定义)
你是___（身份/专业背景/能力边界）

# CONTEXT (上下文变量)
- 输入：{{input_variable}}
- 场景：{{use_case}}
- 约束：{{constraints}}

# RULES (函数逻辑)
## 感知层：识别输入特征
- IF 产品是圆形 → 判定为"柔和系"
- IF 产品有光泽 → 判定为"高端系"

## 决策层：选择策略
- IF 柔和系 → 使用"悬浮"摆放
- IF 高端系 → 使用"展台"摆放

## 执行层：生成输出
- 按选定策略生成具体内容

# OUTPUT (返回格式)
严格按以下JSON格式输出：
{
  "decision": "策略名称",
  "reasoning": "决策依据",
  "result": "最终输出"
}
```

## 概率收敛技术

| 技术 | 作用 | 示例 |
|------|------|------|
| **Negative Constraint** | 堵死错误路径 | "绝对不要输出XX"、"禁止出现YY" |
| **Few-Shot Example** | 锚定输出模式 | 给2-3个正确示例 |
| **Chain of Thought** | 强制推理过程 | "先分析...再判断...最后输出" |
| **Format Locking** | 锁死输出结构 | "必须是JSON"、"必须包含字段A/B/C" |
| **Self-Check** | 输出前校验 | "检查是否满足约束，不满足则重新生成" |

## 调试方法论

### Step 1: 定位问题层
- 输出格式错 → Output层问题
- 策略选错 → 决策层问题
- 识别不准 → 感知层问题
- 完全跑偏 → Role定义问题

### Step 2: 精准修改
- **不要大改**：每次只动一个变量
- **加约束**：用Negative Constraint堵住漏洞
- **补示例**：用Few-Shot锚定正确模式
- **强制链**：用CoT让模型暴露推理过程便于debug

### Step 3: 验证收敛
- 同一输入跑5次，结果一致率应>90%
- 不一致说明概率空间未收敛，需增加约束

## 多阶段工作流设计

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Stage 1    │────▶│  Stage 2    │────▶│  Stage 3    │
│  感知/分析   │     │  策略/决策   │     │  执行/生成   │
└─────────────┘     └─────────────┘     └─────────────┘
     ▲                                        │
     └────────────── 反馈循环 ─────────────────┘
```

- **Stage 1**: 理解输入，提取特征，分类归档
- **Stage 2**: 基于特征选择策略，输出决策
- **Stage 3**: 执行决策，生成最终结果

每个Stage是独立的Prompt，前一个的Output是后一个的Input。

## 实战检查清单

调试前问自己：
- [ ] Role 定义是否清晰？（模型知道自己是谁）
- [ ] 约束是否足够？（错误路径是否堵死）
- [ ] 有没有示例？（模型见过正确答案长什么样）
- [ ] 输出格式是否锁定？（不锁定则随机）
- [ ] 推理过程是否可见？（不可见则无法debug）
